# 로컬 게임 Q&A 테스트 UI 설계

## 목적

외부 업무생산성 서비스와 연결하기 전에 Game Q&A API의 질문·응답 흐름을 브라우저에서 직접 확인할 수 있는 개발용 테스트 화면을 제공한다.

## 범위

- `GET /`에서 로컬 테스트 UI 제공
- 기존 `POST /api/ask` 계약 재사용
- 서버 상태 확인
- 질문 입력 및 응답 표시
- `mode` 선택
- API 인증키 입력 지원
- 오류 상태를 사용자가 이해할 수 있는 문장으로 표시

## 제외 범위

- 회원가입·로그인
- 대화 저장 및 검색
- 외부 업무생산성 서비스 UI
- MCP Host 구현
- 스트리밍 응답
- 브라우저의 인증키 저장

## 선택한 접근

Node 기본 HTTP 서버가 정적 HTML, CSS, JavaScript 파일을 직접 제공한다. 별도 프론트엔드 프레임워크나 빌드 도구를 추가하지 않아 설치 비용과 토큰·운영 복잡도를 줄인다. 실제 업무생산성 서비스가 연결된 뒤에도 개발용 API 검증 화면으로 유지할 수 있다.

## 화면 구성

1. 헤더: 서비스명과 API 상태 배지
2. 설정 영역: API 주소, 선택적 API 키, 질문 모드
3. 질문 영역: 질문 입력창과 전송 버튼
4. 응답 영역: 답변, 에이전트, 신뢰도, 출처
5. 오류 영역: 인증 실패·모델 오류·데이터 없음·네트워크 오류 안내

API 키는 `localStorage`나 쿠키에 저장하지 않는다. 입력값은 요청을 보낼 때만 `Authorization: Bearer <key>` 헤더에 사용한다.

## 데이터 흐름

```text
브라우저
  -> GET /health
  -> POST /api/ask { mode, question }
  <- JSON 응답
  -> 화면에 답변·출처·메타데이터 표시
```

## 인증 동작

- API 키 입력란이 비어 있으면 인증 헤더를 보내지 않는다.
- 서버의 `API_KEY`가 비어 있으면 인증 없이 로컬 테스트한다.
- 서버가 인증을 요구할 때 키가 없거나 잘못되면 `401` 안내를 표시한다.
- 키는 화면 새로고침 후에도 유지하지 않는다.

## 오류 처리

- 서버 상태 확인 실패: 서버 실행 여부와 `npm start` 안내
- `401`: API 키 설정 또는 입력 확인 안내
- `404`·`400`: 요청 형식 및 서버 버전 안내
- `5xx`: 모델 키, 모델 URL, 모델 응답 상태 확인 안내
- 네트워크 오류: API 주소와 서버 실행 상태 안내

## 테스트 기준

- 루트 경로가 HTML 문서를 반환한다.
- UI가 `/health`를 호출해 상태를 표시한다.
- 질문 제출 시 `/api/ask`에 선택한 모드와 질문을 전송한다.
- API 키가 입력된 경우에만 Bearer 헤더를 전송한다.
- 정상 응답의 답변과 메타데이터를 표시한다.
- 인증 실패 응답을 사용자 안내문으로 표시한다.
- 기존 API 테스트가 모두 통과한다.

## 완료 조건

`npm start` 실행 후 브라우저에서 `http://localhost:3000/`을 열고, 별도 프론트엔드 설치 없이 질문을 전송해 응답을 확인할 수 있다.
